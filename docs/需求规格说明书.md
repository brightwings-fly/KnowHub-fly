## 1. 项目背景与目标

### 1.1 项目背景

当前，王锦成通过助理（飞翔）为其双胞胎儿子王皓飞（成都信息工程大学信息安全专业）和王皓翔（成都锦城学院计算机科学专业）设计每日学习内容。学习内容以共享文件的形式进行管理，文件已累积至数百页，内容涵盖每日学习计划、学习大纲、操作指南等。

随着学习内容的不断积累，共享文件方式日益暴露出以下问题：

- **内容检索困难**：数百页的共享文件中定位特定知识点十分不便；
- **版本管理混乱**：多次编辑后难以追踪内容变更；
- **学习回顾不便**：无法按时间、主题、阶段等维度快速回顾学习记录；
- **缺乏权限控制**：所有内容对所有可见人员开放，无法区分管理者和学习者视角；
- **缺少自动化支持**：无法通过程序自动推送每日学习内容到指定位置。

### 1.2 项目目标

本项目旨在开发一套"学习内容管理系统"（Learning Content Management System, LCMS），作为皓飞和皓翔的实战开发项目。系统需满足以下核心目标：

- 提供一个 B/S 架构的 Web 应用，支持主流浏览器访问；
- 支持管理员与学员两种角色的登录与权限管理；
- 管理员可对学习内容进行增、删、改、查操作；
- 学员可查看、搜索、筛选学习内容；
- 提供 API 接口，支持第三方（如助理角色）自动写入每日学习内容；
- 系统部署简单、运行稳定，适合学生水平的开发环境（Windows）。

### 1.3 项目范围

本系统为独立开发的 Web 应用，不依赖第三方 SaaS 平台。项目交付物包括可运行的系统、源代码仓库、部署说明文档、用户操作手册及 API 接口文档。系统开发周期预计为 4-6 周。

## 2. 系统用户角色

系统设计两种用户角色，其定义和权限如下：

### 2.1 管理员（Admin）

- 登录系统，进入管理后台；
- 管理学员账号（创建、禁用、重置密码）；
- 对学习内容进行增、删、改、查操作；
- 查看系统操作日志（如内容变更记录）；
- 管理内容分类/标签（需设计实现）；
- 调用 API 凭据管理（生成/吊销 API Token）。

### 2.2 学员（Student）

- 登录系统，进入学习视图；
- 浏览、搜索、筛选学习内容；
- 按日期、分类、关键词检索内容；
- 标记已学习/收藏内容（可选功能，推荐实现）；
- 查看个人学习进度概览（可选功能）。

> 注意：学员不具备内容管理权限，无法编辑或删除学习内容。

## 3. 功能需求详细描述

### 3.1 用户认证模块

系统应提供完整的用户认证功能：

- **用户注册**：仅管理员可通过管理后台创建学员账号，不支持公开注册；
- **用户登录**：支持用户名/邮箱 + 密码登录，登录后生成会话（Session 或 JWT）；
- **密码管理**：管理员可重置学员密码；
- **登录状态保持**：提供"记住我"功能，会话有效期至少 7 天；
- **登出**：用户可主动登出系统，清除会话。

### 3.2 管理员功能模块

#### 3.2.1 管理后台概览

管理员登录后进入管理后台首页，应展示：

- **系统概览**：内容总数、学员数、近 7 天新增内容数；
- **快捷入口**：快速添加内容、查看最新内容、管理学员。

#### 3.2.2 学习内容管理

管理员对学习内容进行全生命周期管理：

- **添加内容**：支持标题、正文（富文本编辑器或 Markdown）、分类/标签、关联日期；
- **编辑内容**：支持修改已发布的任何内容；
- **删除内容**：支持软删除（保留数据但不展示给学员）或硬删除；
- **查看内容列表**：列表展示标题、分类、发布日期、最后编辑时间，支持排序和分页；
- **内容分类管理**：支持自定义分类/标签，支持树形或扁平分类。

#### 3.2.3 学员管理

管理员可管理学员账号：

- **创建学员账号**：输入用户名、密码、显示名称；
- **查看学员列表**：展示学员用户名、注册时间、最后登录时间、学习内容查看次数；
- **禁用/启用账号**：管理员可临时禁用学员账号；
- **重置密码**：管理员可为学员重置为默认密码或随机密码。

#### 3.2.4 API 凭据管理

管理员可管理 API 调用凭据：

- **生成 API Token**：为第三方调用生成唯一的 Token；
- **吊销 API Token**：随时吊销不再使用的 Token；
- **查看 Token 使用记录**：最近调用时间、调用次数等。

### 3.3 学员功能模块

#### 3.3.1 学习首页

学员登录后进入学习首页，应展示：

- **今日学习内容（如果有）**：突出展示当日推送的学习内容；
- **最新内容列表**：按时间倒序展示最新学习内容；
- **快捷搜索框**：输入关键词快速定位内容；
- **学习进度概览（可选）**：已读/未读内容比例。

#### 3.3.2 内容浏览与搜索

学员可浏览和搜索学习内容：

- **内容列表页**：按时间倒序分页展示学习内容，可切换按分类筛选；
- **内容详情页**：展示内容标题、正文、分类标签、发布日期；
- **全文搜索**：按标题或正文关键词搜索相关学习内容；
- **按日期筛选**：选择日期范围，查看该期间的学习内容；
- **按分类筛选**：点击分类/标签，查看该分类下所有内容；
- **内容收藏（可选）**：学员可收藏感兴趣的内容，在"我的收藏"中统一查看。

### 3.4 API 接口模块

系统需提供 RESTful API 接口，供助理角色（或其他第三方系统）自动写入每日学习内容。API 设计需遵循以下原则：

- 使用 HTTP/HTTPS 协议，请求和响应格式为 JSON；
- 接口认证采用 Token 机制（Bearer Token）；
- 提供清晰的错误码和错误信息；
- 接口文档需详细说明每个接口的请求方法、路径、参数和响应格式。

#### 3.4.1 核心 API 接口列表

| 接口名称 | HTTP 方法 | 路径 | 说明 |
|----------|-----------|------|------|
| 创建内容 | POST | /api/v1/contents | 新增一条学习内容 |
| 获取内容列表 | GET | /api/v1/contents | 分页获取内容列表，支持筛选 |
| 获取内容详情 | GET | /api/v1/contents/{id} | 获取单条内容详情 |
| 更新内容 | PUT | /api/v1/contents/{id} | 修改内容（需管理员 Token） |
| 删除内容 | DELETE | /api/v1/contents/{id} | 删除内容（需管理员 Token） |
| 获取系统状态 | GET | /api/v1/health | API 健康检查 |

#### 3.4.2 API 认证方式

所有 API 请求需在 HTTP Header 中添加 `Authorization: Bearer <token>`，Token 由管理员在管理后台生成。创建/更新/删除操作 Token 需对应管理员权限，查询操作可使用学员级别 Token。

## 4. 非功能需求

### 4.1 安全需求

- **密码存储**：用户密码必须经哈希处理（推荐 bcrypt 或 argon2），严禁明文存储；
- **会话安全**：登录会话应使用安全的随机字符串或 JWT，设置合理过期时间；
- **SQL 注入防护**：所有数据库操作应使用参数化查询或 ORM 框架；
- **XSS 防护**：用户输入内容在显示前应进行转义处理；
- **API 认证**：API 接口必须验证 Token 有效性；
- **HTTPS 支持（如有公网部署）**：建议配置 SSL 证书。

### 4.2 性能需求

- **页面加载**：主要页面加载时间不超过 2 秒；
- **内容检索**：关键词搜索响应时间不超过 3 秒（内容量 < 10000 条时）；
- **并发用户**：支持至少 10 个用户同时在线使用；
- **API 响应**：API 接口平均响应时间不超过 500ms。

### 4.3 兼容性需求

- **操作系统服务端**：Windows 10/11 或 Linux（推荐使用 Windows，方便学生调试）；
- **浏览器兼容**：Chrome、Edge、Firefox 最新版本；
- **数据库**：MySQL；
- **客户端**：无特别配置要求，通过浏览器即可访问。

### 4.4 可用性需求

- **界面语言**：中文（简体）用户界面；
- **操作反馈**：所有操作应有明确的成功/失败提示信息；
- **响应式布局**：建议适配 PC 端和移动端浏览器（至少保障 PC 端体验）；
- **错误提示**：系统错误应给出用户可理解的提示，而非技术堆栈信息。

## 5. 技术选型建议

以下技术选型建议为参考方向，乙方可提出备选方案经甲方确认后执行。选型原则为：适合学生水平、社区活跃度高、文档齐全、Windows 友好。

| 技术领域 | 推荐方案 | 备选方案 |
|----------|----------|----------|
| 后端框架 | Python Flask | Node.js Express / Java Spring Boot |
| 前端框架 | Vue.js 3 或 React | 原生 HTML+CSS+JS / Bootstrap |
| 数据库 | MySQL（生产） | PostgreSQL |
| ORM / 数据库操作 | SQLAlchemy（Python） | Prisma（Node.js） |
| 认证方案 | Flask-Login / JWT | Session-based Auth |
| 部署方式 | 本地运行 + 内网穿透（如需外网访问） | Docker 容器化 |

特别说明：推荐 **Python + Flask + MySQL** 的组合，因为三位开发者（皓飞、皓翔、飞翔助理）对 Python 相对熟悉，Flask 轻量简单容易上手。

## 7. 验收标准

以下验收标准将作为项目交付评估的依据。每项验收结果分为"通过"或"不通过"，全部通过即为项目验收合格。

### 7.1 功能验收

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| F-01 | 管理员登录 | 使用管理员账号密码成功登录，错误密码登录被拒绝 |
| F-02 | 学员登录 | 使用学员账号密码成功登录，错误密码登录被拒绝 |
| F-03 | 添加学习内容 | 管理员成功添加一条含标题、正文、分类的学习内容 |
| F-04 | 编辑学习内容 | 管理员成功修改已有内容的标题和正文 |
| F-05 | 删除学习内容 | 管理员成功删除一条学习内容，内容不再显示给学员 |
| F-06 | 内容搜索 | 学员按关键词搜索出相关学习内容 |
| F-07 | 内容分类筛选 | 学员按分类筛选出对应内容 |
| F-08 | API 创建内容 | 通过 API 成功创建一条学习内容，返回 201 状态码 |
| F-09 | API 获取内容 | 通过 API 成功获取内容列表和单条内容详情 |
| F-10 | 学员权限隔离 | 学员登录后无法访问管理后台功能 |

### 7.2 非功能验收

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| NF-01 | 密码安全 | 数据库中的密码为哈希值，非明文 |
| NF-02 | 部署文档 | 按部署文档可在 Windows 上成功搭建并运行系统 |
| NF-03 | 操作手册 | 操作手册完整，管理员和学员可对照操作 |
| NF-04 | API 文档 | API 文档完整，每个接口有请求示例和响应示例 |
| NF-05 | 源代码提交 | 源代码已提交至 Git 仓库，包含 README |
